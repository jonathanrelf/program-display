# Security policy

## Supported versions

Before the first stable release, only the newest tagged preview receives
security fixes.

## Reporting a vulnerability

Please do not open a public issue for a vulnerability or for logs containing
private device information. Use GitHub's private vulnerability reporting for
this repository once it is published. Include the affected version, impact,
reproduction steps and the smallest necessary sanitised evidence.

Never include raw EDID data, hardware serial numbers, credentials or complete
unreviewed OBS logs. Display hashes emitted by the optional diagnostic probe are
persistent pseudonymous identifiers and should also be treated as sensitive.
